What the website does

What the watchdog accesses

The Gmail reader can read mailbox information under the gmail.readonly permission. Its intended searches are limited to the exact daily audit report and its metadata and status record. The alert sender uses gmail.send to send watchdog notices to the owner and gmail.readonly to avoid duplicate sends and verify the exact new email’s recipient, content and inbox placement. No permission to delete or modify messages is requested by these credentials.

The daily audit report can include project names, delivery status, dates, saved-artifact references, email receipt identifiers and unresolved gaps. The watchdog’s status check is not an independent examination of every underlying deliverable.

Storage and processing

OAuth credential files are retained on the owner’s computer. With the owner’s authorization, copies are stored as encrypted GitHub Actions repository secrets in the private watchdog repository. During an explicitly started test or a future authorized scheduled run, GitHub-hosted execution processes the credentials and relevant Gmail API results. The credentials are not intended for source commits, downloads, public pages or logs.

Failure logs are designed to contain sanitized error categories rather than token values or full email bodies. Test records can include timestamps, result flags and the exact test message identifier. Gmail stores sent test and alert messages. Private ChatGPT audit records store reconciliation evidence and references; that is separate from these public informational pages.

Sharing and retention

The setup does not sell Gmail data, use it for advertising or use it to train models. Google processes Gmail/API requests; GitHub processes workflow execution and secrets; the owner’s connected ChatGPT tools process the audit records they are explicitly asked to handle. Access is limited by the relevant account and repository permissions.

Records remain in their configured services until removed under the owner’s settings or those services’ retention rules. This draft does not establish a new automatic deletion schedule. The owner should inspect the configured retention before enabling unattended operation.

Control and revocation

The owner can revoke the app’s access in Google Account third-party connections, remove the encrypted GitHub secrets, disable the workflow and delete local credential files. Revocation stops future authorized API access; it does not automatically remove records already stored in Gmail, GitHub or the audit register. Those records can be managed separately.

Google user data is intended to be used only for the personal delivery-checking purposes disclosed here. Changes to permissions, recipients, hosting or data use require review and an updated disclosure.
